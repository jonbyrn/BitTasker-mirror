### npm Dependencies (latest stable at time of writing)

```
@bgd-labs/aave-address-book@4.44.22    # contract addresses, TypeScript types
@aave/core-v3@1.19.3                    # ABI definitions, DataTypes, IPool interface
@uniswap/v3-sdk@3.30.3                  # position math (ticks → price ranges)
@uniswap/sdk-core@7.16.1                # underlying SDK (ChainId, Token, etc.)
ethers@^6.15.0                           # already in project, compatible with all above
```

Why each:

- `@bgd-labs/aave-address-book`: Canonical source of truth for Aave contract addresses across all chains. Avoids hardcoding.
- `@aave/core-v3`: Provides `IPool.sol`, `IPoolDataProvider.sol`, `DataTypes.sol` as typed ABIs. Also includes error types for decoding contract reverts — critical for the "distinguish contract revert from provider error" logic.
- `@uniswap/v3-sdk`: `Pool`, `Position`, `NonfungiblePositionManager`, `tickToPrice`, `priceToClosestTick` — all the math needed to show APY estimates, compute liquidity amounts, and determine if a position is in-range.
- `@uniswap/sdk-core`: `Token`, `CurrencyAmount` — required by v3-sdk.

No additional SDKs needed:

- Aave has no maintained JavaScript SDK beyond `core-v3` + `address-book`
- LI.FI / Symbiosis: REST APIs only, no TypeScript SDKs (already integrated in project via `lifi.service.ts`, `symbiosis.service.ts`)
- Boltz: REST API, no TypeScript SDK (irrelevant — has no WBTC pairs)

## 6. Cross-Chain Swap Integration — PHASE 5

### Verified routes (tested live May 28, 2026)

| Route                             | Provider               | Status           | Fee        | Notes                                    |
| --------------------------------- | ---------------------- | ---------------- | ---------- | ---------------------------------------- |
| **RBTC (RSK) → WBTC (Arbitrum)**  | LI.FI via Symbiosis    | ✅ **CONFIRMED** | ~0.5%      | 2-step: feeCollection + symbiosis bridge |
| WBTC (Ethereum) → WBTC (Arbitrum) | LI.FI via Garden       | ✅ Confirmed     | ~0.3%      | $49.7M volume                            |
| WBTC ↔ USDT0 (Arbitrum)          | Uniswap V3 on Arbitrum | ✅ Native        | 0.05% pool | $16M/day volume                          |

**The RSK → Arbitrum WBTC route works.** LI.FI returns quotes with `"tool": "symbiosis"` bridging from chain 30 (RSK) to chain 42161 (Arbitrum). For 0.001 RBTC, the effective fee is ~0.5% — competitive.

### "Get WBTC" CTA flow

Opens existing SwapForm with destination token pre-selected to WBTC (Arbitrum at `0x2f2a2543B76A4166549F7aaB2e75Bef0aefC5B0f`).
Source defaults to the user's highest-value wallet (built-in RBTC or connected USDT0).
If both RBTC and USDT0 are available: RBTC takes priority (directer route).
Swap executes via LI.FI/Symbiosis integration already in the project.

### NOT using Powpeg

The RSK Powpeg (BTC→RBTC via 2-way peg) is too slow (hours-to-days for confirmation). Not viable for DeFi flows.
The Symbiosis bridge route uses RBTC on RSK directly — no BTC mainchain hop needed.

## 7. Transaction Safety Requirements

### Chain-ID Guard (CRITICAL)

Before EVERY `eth_sendTransaction`: verify `chainId === 42161` (Arbitrum One).
Reuse existing `chainLock` from `wallet.store.ts`.
Show "Wrong network — switch to Arbitrum" button if chain mismatch.

### Pending Transaction State

Persist to localStorage: `{type, txHash, chainId, timestamp}`.
On mount: check for pending tx → rehydrate status → show "Transaction processing..." banner.
Prevents double-submit when user closes/reopens app during pending tx.

### Approval Flow (Two-Step)

```
[Approve & Borrow] click →
  Step 1: Check allowance → if insufficient, prompt approve tx → wait for confirmation
  Step 2: Execute borrow → wait for confirmation
  Step 3: Show success + position card
```

Show loading indicators between steps.
For USDT0: use `forceApprove` pattern (reset to 0 first if needed).
Infinite approval for Aave (one-time per user). Exact approval for Uniswap.

### Failed Transaction Recovery

Distinguish: user rejection (no gas cost) vs on-chain revert (gas consumed).
Show tx hash + decoded revert reason for reverts.
Offer "Revoke Approval" button for dangling approvals.

### Gas Price

Refetch `eth_gasPrice` at confirmation (not from 30s cache).
Offer: slow/standard/fast gas options.

## 10. Edge Cases & Error States (Expanded)

| Edge Case                             | Risk         | Handling                                                       |
| ------------------------------------- | ------------ | -------------------------------------------------------------- |
| Wrong chain (MetaMask on Ethereum)    | **CRITICAL** | Chain-ID guard (42161). "Switch to Arbitrum" prompt            |
| App close during pending tx           | **CRITICAL** | localStorage persistence + rehydrate on mount                  |
| Aave reserve frozen/paused            | **HIGH**     | Check `isFrozen()` / `isPaused()` before each operation        |
| Aave LTV changed mid-flow             | **HIGH**     | Re-read reserve data at confirmation. Show diff warning        |
| Stale rate (>0.5% change)             | **HIGH**     | Re-read rate at confirmation. Show old→new delta               |
| Gas too high (>$5)                    | **HIGH**     | Warning with cost estimate. Offer to wait                      |
| Uniswap pool not deployed (0.3% tier) | **HIGH**     | `getPool()` check. Hide non-existent fee tiers                 |
| USDT0 approval race condition         | **HIGH**     | `forceApprove` pattern (check → reset if needed → approve)     |
| No WBTC balance                       | **MEDIUM**   | "Get WBTC" CTA → SwapForm pre-filled                           |
| No USDT0 balance (Earn)               | **MEDIUM**   | "Get USDT0" CTA → SwapForm pre-filled                          |
| Pool at capacity                      | **MEDIUM**   | Grey out. Show "Pool at capacity — try smaller amount or wait" |
| WBTC depeg (divergence from BTC)      | **MEDIUM**   | Monitor WBTC/BTC oracle diff. Warn if >1%                      |
| Health factor < 1.1                   | **MEDIUM**   | Red banner. Suggest add collateral. Background alert           |
| Failed tx — on-chain revert           | **MEDIUM**   | Show tx hash + decoded reason. Offer revoke approval           |
| LP out of range (v2)                  | **LOW**      | "Not earning fees — rebalance"                                 |
| Rate changes during confirmation      | **LOW**      | Toast: "Rate updated. Recalculated."                           |

## 13. UX Principles (Revised Post-Audit)

1. **The input and CTA are always visible.** Supporting data (fees, health, collateral) is collapsed by default and one tap away. CTA is pinned to drawer footer.
2. **Show, don't ask — and show requirements.** Display what the user needs (WBTC, USDT0) before they type anything. Pre-check cards prevent dead ends.
3. **Two tabs, not three.** "Earn" with sub-selector eliminates label confusion.
4. **Accessible by default.** Health gauge uses color + number + text + aria-meter. All four channels work together.
5. **Safety-first.** Chain-ID guard, pending tx persistence, approval lifecycle, re-read critical data at confirmation.
6. **Mobile-first.** All critical UI fits 375px viewport with collapsible sections and footer-pinned CTA. Content scrolls — input and CTA don't.
7. **Reuse existing patterns.** WalletSelector, amount input + max join, fee card, collapse accordion, skeleton loading — all from existing code conventions.

```bash
# JS evaluation test (connect to existing session, find wallet page, evaluate)
node -e '
const { chromium } = require("playwright");
(async () => {
  const browser = await chromium.connectOverCDP("http://localhost:9222");
  const ctx = browser.contexts()[0];
  const page = ctx.pages().find(p => p.url().includes("/dashboard/wallet")
    && !p.url().includes("(protected)"));
  if (!page) { console.log("no wallet page"); await browser.close(); return; }

  // ... test logic ...

  await browser.close();
})();
'
```
